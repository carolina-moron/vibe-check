Vibe Check — Peer Review

Date: September 14, 2026 | Reviewer: Claude
Project: Static no-build safety-check app for trafficking/scam risk assessment

Executive Summary

Status: ✓ Functional MVP with strong foundations; ready for user testing

Strengths

  • ✓ Clear methodology, multi-register architecture, honest scoring model (no false "clear")
  • ✓ Excellent sourcing discipline; all cases verified against DOJ, FinCEN, UNODC
  • ✓ Pessimistic verification model protects users (unverified by default)

Gaps

  • ⚠ Report backend undefined; forms build correctly but nothing submits
  • ⚠ CTDC integration pending (data needs manual CSV import)
  • ⚠ Limited geographic coverage (US/EU-centric registers)

Risk

  • ⚠ Legal/defamation risk if screening logic keys on geography (e.g., flagging all US small businesses because CPI score is low) instead of entity-specific conduct. Sayari handoff warned on this.

Architecture & Code Quality

Core Engine src/engine.js B+

629 lines • Pure functions • No side effects

  • ✓ Pessimistic scoring: unverified by default (safe for users)
  • ✓ Exact-name-only matching prevents false positives ("Quillmere Freight" vs "Northfield Logistics")
  • ⚠ assess() is 100+ lines; could split into assessOrganisation(), assessText(), assessDomain()
  • ⚠ No caching of register lookups; every check re-queries

UI & State src/app.js B

1,714 lines • Modular views • Hash routing

  • ✓ Clean view functions (viewCheck, viewCases, viewTeam, etc.)
  • ✓ Responsive routing with hash-based navigation
  • ⚠ Single 1,700-line file; consider splitting into views/, components/, pages/
  • ⚠ Inline SVG namespacing in HTML; could cause parsing issues

Visual Design src/figure.js, src/styles.css A−

Globe animation • Paper aesthetic • Responsive

  • ✓ Globe animation shows 20 trafficking corridor endpoints (real coordinates)
  • ✓ Color coding clear: red=sources, blue=transit/destination
  • ✓ Paper aesthetic consistent (beige + navy + accent blue)
  • ⚠ Cylindrical projection distorts poles (minor; not critical for UI)

Data Integrity & Sourcing

Cases A

  • ✓ 20 documented cases; all sourced to DOJ, FinCEN, UNODC
  • ✓ NXIVM case excellent true positive: Keith Raniere conviction (120 years), beneficial owners
  • ✓ No victim names; unnamed entities excluded from matching
  • ✓ Methodology page transparent about FCRA constraints
  • ⚠ Cases are static; no automated DOJ press release updates

Signal Taxonomy A−

  • ✓ 50 signals in 6 dimensions (identity, money, pressure, isolation, travel, record)
  • ✓ Weights assigned (low/medium/high) with justification
  • ⚠ Some signals under-tested (followers_fake, images_ai — no test cases verify these)

User Experience

Strengths

  • ✓ Clear value prop: "Something feels off? Check the vibe." (vs. vague "safety score")
  • ✓ Multiple input paths: profile, screenshot (OCR), job posting, free text
  • ✓ Honest results: shows "Unverified" when incomplete, not "clear"
  • ✓ Privacy-first: removes personal details before preview; photo → perceptual hash only
  • ✓ Help integration: hotlines on every page; quick-exit button

Gaps

  • ⚠ Report backend is null: forms build/preview, but nothing submits
  • ⚠ CTDC not loaded: feature ready, but data needs manual import
  • ⚠ Screenshot OCR slow: Tesseract.js blocks UI for 3–5 seconds on large images
  • ⚠ No offline mode: register timeout shows "could not search" without manual fallback

Recommendations

  1. Disable report form if REPORT_ENDPOINT === null, or show "reporting coming soon"
  2. Add loading state during OCR: "Reading screenshot… 45%"
  3. Offer manual register links if lookup fails: "Search by hand here: [DOL] [OpenSanctions] [BBB]"

Legal & Compliance

Strengths

  • ✓ FCRA-compliant: no person checks, no criminal-record lookups
  • ✓ Methodology page discloses limitations
  • ✓ Coverage model shown: what was searched, what couldn't be reached

Risks

  • ⚠ False positive on geography: If logic flags "US small business" because CPI is low, product becomes defamatory. Sayari handoff warned on this. Current logic appears sound (entity-specific flags only), but audit regularly.
  • ⚠ Benchmark clarity: "Serious warning signs" tier could be misread as "conviction." Consider: "High concern — requires verification before proceeding"
  • ✓ Religious organization exclusion (BAPS) correctly identified; good precedent to document

Testing

31 unit tests • All pass

  • ✓ Covers: exact-name matching, verification model, corridor parsing, news aggregation
  • ⚠ No integration tests (screenshot → OCR → check → report preview)
  • ⚠ No E2E tests (actual register queries)
  • ⚠ No accessibility tests (keyboard, screen reader, WCAG AA)

Performance

Grade: B

  • ✓ Static site; no server required
  • ✓ Lazy-load news data (on-demand)
  • ✓ 12-second timeout on register queries (prevents blocking)
  • ⚠ No code splitting; app.js is 1,714 lines in single module
  • ⚠ No caching of register results
  • ⚠ Tesseract.js is ~400KB; slow on 3G

Recommendations

  1. Cache register results in sessionStorage (30-min TTL)
  2. Lazy-load Tesseract only when screenshot tab clicked
  3. Split app.js into views/ + components/ for faster parsing

Accessibility

Grade: B−

  • ✓ Semantic HTML; ARIA live regions; skip link
  • ✓ 13:1 contrast (navy on beige)
  • ⚠ Color-only indicators (red=high, blue=normal) — needs label
  • ⚠ No keyboard-only navigation test
  • ⚠ Animation can't be paused (only respects prefers-reduced-motion)

Quick Wins

  1. Add aria-label to risk color badges ("High concern: red")
  2. Keyboard navigation audit (Tab through entire form)
  3. Add pause button to globe animation

Conclusion

Vibe Check is a thoughtfully designed, well-sourced safety-check tool. The pessimistic scoring model (unverified by default), exact-name matching to avoid false positives, and transparent methodology set it apart from clickbait "scam checkers."

Ready for:

  • ✓ User testing with beta cohort
  • ✓ Security audit (anonymisation, privacy)
  • ✓ Legal review (defamation, FCRA compliance)

Not ready for:

  • ⚠ Public launch (report backend missing; UX falls short when registers timeout)
  • ⚠ Platform integration (APIs not built yet)
Overall: B+ (75–85%)
Solid foundation. Ship with backend and fallback UX. Plan Phase 2 in Q4.
